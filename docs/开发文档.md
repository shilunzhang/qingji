## 1. 项目概述

### 1.1 一句话定位
「轻记」是一款主打**轻松、省心、易用**的 iOS 个人记账 App，对标「团团记账」的轻量路线：3 秒记一笔、能自动就自动、不强求完美记账。

### 1.2 目标用户
- 有记账意愿但嫌麻烦的年轻人（主力场景：支付宝/微信/信用卡消费）
- 需要多账户（现金/储蓄卡/支付宝/微信/信用卡）统一管理余额与流水的用户

### 1.3 核心价值
1. **快**：记账路径 ≤ 3 步（金额 → 分类 → 保存）
2. **省**：截图/账单导入等「准自动」记账，减少手动输入
3. **清**：日历、图表、账户三条线查账，账目一目了然
4. **智**：AI 理解自然语言、自动分类、生成账单解读

### 1.4 本期范围
- **M1（当前）**：手动记账、多账户、分类统计、记账日历、备注凭证、预算、周期记账、iCloud 同步、App 锁、CSV 导出
- **M2**：截图 OCR 记账、支付宝/微信账单导入、**自动记账（快捷指令自动截图 Tier 1 + 相册扫描 Tier 2 + 统一防重闸门，见 F-12/F-13/F-14）**、Widget/Siri/快捷指令入口、年视图热力图
- **M3**：AI 全家桶（自然语言记账、语音记账、账本问答、月度 AI 解读、智能导入清洗）、Apple Watch

## 2. 技术决策记录（ADR）

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| D1 | 最低系统版本 | **iOS 18.0** | SwiftData / 控制中心 / Swift Charts 成熟；2026 年覆盖率足够。AI 端侧模型（iOS 26 Foundation Models）在 M3 以条件编译接入 |
| D2 | UI 框架 | **SwiftUI + MVVM** | 声明式 UI 开发效率高；项目无历史包袱 |
| D3 | 持久化 | **SwiftData** | 与 SwiftUI 深度集成；配合 CloudKit 自动云同步 |
| D4 | 云同步 | **CloudKit（ModelConfiguration.cloudKitDatabase = .automatic）** | 免账号体系、免服务器、数据存用户自己的 iCloud。无 iCloud 权限时自动降级为本地存储 |
| D5 | 金额存储 | **Int64「分」为最小单位，禁止 Double** | 浮点误差不可接受；CloudKit 不支持 Decimal 类型，Int64 天然兼容 |
| D6 | 枚举存储 | 模型中存 `String rawValue` + 计算属性还原枚举 | 规避 `#Predicate` 对枚举的兼容性问题；便于后续按类型查询 |
| D7 | 查询策略 | MVP 阶段 `@Query` 全量取数 + 内存聚合过滤 | 个人账本量级（数万条内）性能足够；避免手写复杂 `#Predicate` 引发编译/运行时问题。性能优化（分页/索引）列为 M2 技术债（§9.4） |
| D8 | 自动记账路线（M2） | **截图 OCR + 账单导入**为主，快捷指令/剪贴板为辅 | iOS 沙盒无法读取支付宝/微信通知，「通知监听全自动」不可行；截图分享 + Vision OCR 体验最接近自动且无需后端 |
| D9 | AI 路线（M3） | **端侧优先（Foundation Models, iOS 26+）+ 云端 LLM 可选** | 端侧零成本、隐私、离线；低版本/高级能力走云端，成本由用户 Key 或订阅覆盖 |
| D10 | 开发环境 | 代码在 Windows 编写，**编译/测试走 GitHub Actions macOS runner** | 本机无 Xcode；CI 产出构建结果，可扩展 TestFlight 分发 |
| D11 | 工程生成 | **XcodeGen（project.yml）生成 .xcodeproj** | 手写 pbxproj 易错且无法评审；xcodegen 声明式、可版本化 |
| D12 | 第三方依赖 | **M1/M2 零第三方依赖** | 标准库足够（SwiftData/Charts/Vision/Speech/LocalAuthentication），降低维护成本 |
| D13 | 货币 | M1 仅人民币（字段预留 `currencyCode`） | 满足本土场景；多币种为远期需求 |
| D14 | 隐私合规 | 本地优先；仅用户显式使用云端 AI 时上传必要文本；含 Face ID 权限说明 | 符合《个人信息保护法》最小必要原则 |
| D15 | 自动记账路线（M2 后半） | **快捷指令自动化（关闭支付 App → 自动截图 → OCR → 通知确认）为 Tier 1，相册扫描为 Tier 2**；不做通知监听 | iOS 沙盒禁止读取第三方通知/流水，快捷指令自动化是唯一接近无感的官方通道；快照移交后立即删除、全本地解析；Tier 2 供不接受自动截屏的用户 |
| D16 | 防重策略 | **±10 分钟「方向+金额」窗口统一闸门（DuplicateGuard）**，所有入账入口强制经过；截图指纹防同页重处理 | 重复入账是自动记账的最大风险；窗口匹配覆盖 OCR 时间与账单时间的秒级偏差；指纹缓存存 UserDefaults（7 天过期自动清理） |

## 3. 系统架构

### 3.1 分层

```
┌─────────────────────────────────────────────┐
│ Features（页面）                             │
│   Overview / Stats / Calendar / Mine / Add  │
├─────────────────────────────────────────────┤
│ Components（通用组件） TransactionRow 等      │
├─────────────────────────────────────────────┤
│ Services（业务逻辑，纯函数优先）              │
│   SeedService / StatsService / CSVExporter  │
│   CategoryPredictor / RecurringEngine / AppLockManager │
├─────────────────────────────────────────────┤
│ Models（SwiftData @Model，仅存储与读写）       │
├─────────────────────────────────────────────┤
│ Utilities（Money / DateHelpers / Theme）     │
└─────────────────────────────────────────────┘
```

原则：
- **Models 不含业务逻辑**（只允许类型转换计算属性）
- **Services 尽量纯函数**（输入 `[Transaction]`/`Date` 输出结果），保证可单测
- **视图不直接做金额/日期运算**，一律调用 Utilities

### 3.2 目录结构

```
QingJi/
├── docs/开发文档.md
├── project.yml                 # XcodeGen 工程定义
├── README.md
├── .github/workflows/ios.yml   # macOS CI：生成工程 → 编译 → 单测
└── QingJi/                     # App 主 target
    ├── QingJiApp.swift         # 入口 + ModelContainer
    ├── QingJi.entitlements     # iCloud/CloudKit
    ├── Assets.xcassets         # AccentColor / AppIcon
    ├── Models/                 # Transaction/Account/Category/Tag/Attachment/Budget/RecurringRule
    ├── Services/               # 业务逻辑（含 DuplicateGuard 防重闸门 / PaymentTextParser / BillParser）
    ├── Features/
    │   ├── Root/               # TabView + App 锁遮罩
    │   ├── Overview/           # 明细（流水 + 账户条 + 月汇总）
    │   ├── Add/                # 记账页（键盘/分类/转账/凭证）
    │   ├── Stats/              # 统计图表

    │   ├── Auto/                # 自动记账：通知确认卡 / 自动入账清单 / 配置指引页
    │   └── Mine/               # 我的 + 预算/周期/账户/分类管理

    └── Utilities/              # Money/DateHelpers/Theme
└── QingJiTests/                # 单元测试（纯逻辑 + 内存容器）
```

### 3.3 关键流程

**记一笔**：`AddTransactionView` 收集表单 → `Money.cents(fromString:)` 校验金额 → 创建 `Transaction`（关联 account/category/toAccount）→ `modelContext.insert` → dismiss。
**账户余额**：`余额 = 初始金额 + Σ收入 − Σ支出 − Σ转出 + Σ转入`（信用卡欠款自然表现为负余额）。实时计算、不落库，避免同步冲突。
**净资产**：`Σ 各账户余额`（信用卡为负自动抵扣）。
**周期入账**：App 启动时 `RecurringEngine.postDue` 把到期规则补成流水（`lastPostedDate` 推进防重复）。
**首次启动**：`SeedService.ensureSeeded` 写入内置分类与 5 个默认账户（UserDefaults 幂等标记）。

## 4. 数据模型设计

> 通用约束（CloudKit 要求）：所有属性有默认值或为可选；关系一律可选。金额一律 `Int64` 分。

### 4.1 Transaction（流水）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 主键 |
| kind | String | `expense` / `income` / `transfer`（TxKind.rawValue） |
| amountCents | Int64 | 金额（分），恒为正数，方向由 kind 决定 |
| currencyCode | String | 默认 `CNY` |
| date | Date | 交易时间（允许补记过去时间） |
| note | String | 备注 |
| createdAt / updatedAt | Date | 审计字段 |
| recurringRuleID | UUID? | 周期规则生成的来源标记 |
| account | Account? | 支出/收入账户、转出账户 |
| toAccount | Account? | 转入账户（仅 transfer） |
| category | Category? | 分类（transfer 无） |
| tags | [Tag]? | 标签（M1 模型预留，UI 编辑 M2） |
| attachments | [Attachment]? | 凭证图（级联删除） |
| source | String | 来源：`manual` / `ocr` / `album` / `bill` / `recurring`（防重日志与自动入账撤销清单依赖，D16） |

**不变式**：expense/income 必须有 account 与 category；transfer 必须有 account ≠ toAccount、无 category。

### 4.2 Account（账户）
| 字段 | 类型 | 说明 |
|---|---|---|
| id / name / icon / colorHex | — | 基础信息，icon 为 SF Symbol |
| kind | String | `cash` / `bank` / `alipay` / `wechat` / `credit` |
| initialBalanceCents | Int64 | 期初余额（信用卡通常 0） |
| creditLimitCents | Int64 | 信用额度（仅 credit） |
| billingDay / dueDay | Int | 账单日 / 还款日（仅 credit） |
| sortOrder / isArchived | — | 排序与归档（归档账户不再出现在选择器） |

### 4.3 Category（分类，两级）
| 字段 | 说明 |
|---|---|
| kind | `expense` / `income`；子分类必须与父分类同 kind |
| parent / children | 父子关系；内置父分类见附录 A |
| icon / colorHex / sortOrder | 展示 |
| isSystem | 内置分类不可删除，可改名/换图标 |

### 4.4 Tag / Attachment / Budget / RecurringRule
- **Tag**：name、colorHex、与 Transaction 多对多
- **Attachment**：`data: Data`（`@Attribute(.externalStorage)` 存 JPEG，写入前压缩至长边 ≤1200px）、mimeType、级联挂在 Transaction 上
- **Budget**：`scope = overall | category`；月度预算金额；category 可选；同一 scope 唯一（UI 保证）
- **RecurringRule**：name、kind、amountCents、category、account、frequency（`daily|weekly|monthly|yearly` + 对应参数）、startDate/endDate、lastPostedDate、isActive；到期生成普通 Transaction 并打 `recurringRuleID`
- **截图指纹缓存**（非模型）：UserDefaults 存「金额+页面交易时间(分)+商户」哈希 → 处理时间，条目 7 天过期自动清理；用于拦截同一支付页的重复截图（F-14 第 2 道防线）

## 5. 功能规格

格式：编号 ｜ 名称 ｜ 里程碑。每条含**验收标准（AC）**，M1 功能全部要有 AC。

### F-01 手动记账（M1）
- 底部中央「＋」进入记账页；支出/收入/转账三态切换
- 自定义数字键盘（0-9、小数点、退格、清空）；金额上限 2 位小数
- 智能默认：按时段用 `CategoryPredictor`（历史同时段高频分类）预选分类；默认账户取最近使用
- 转账模式：选择转出/转入账户，不可相同，不选分类
- 可修改交易时间（默认当前）；可填备注、附加 ≤3 张凭证图
- **AC1**：金额→分类→保存 3 次点击内完成一笔支出
- **AC2**：金额为空/为 0 时保存按钮禁用；转账同账户禁止保存
- **AC3**：保存后明细页第一屏可见该流水；编辑已有流水所有字段可改

### F-02 多账户（M1）
- 内置账户类型：现金/储蓄卡/支付宝/微信/信用卡（可增删改、排序、归档）
- 信用卡专属：额度、账单日、还款日；消费后余额为负（负债）
- 明细页顶部账户条：显示各账户余额与净资产（信用卡负数抵扣）
- **AC1**：余额 = 期初 + 收 − 支 − 转出 + 转入，与手工核算一致（有单测）
- **AC2**：删除账户时若有流水，提示先处理流水（M1 阻止删除，仅允许归档）

### F-03 分类与统计（M1）
- 两级分类：内置见附录 A；用户可新增自定义分类（不可删系统分类）
- 统计页：日/周/月/年区间切换；支出/收入切换
- 饼图（分类构成 Top8 + 其他）、趋势图（按日柱状）、分类排行（金额+占比条）
- **AC1**：区间与筛选下的总额 = 明细页同区间总额
- **AC2**：占比之和 = 100%（±0.1%）；无数据时显示空态

### F-04 记账日历（M1）
- 月历：周一为首列；有流水的日期下方显示支出金额（红色小字）；当天圆点标记收入/支出
- 点击日期 → 下方显示当日收/支合计与流水列表，可进入编辑（**改账/补账**）
- 年视图：12 个月的收入/支出/结余汇总列表，点击跳转对应月
- **AC1**：日历某日金额与明细页该日合计一致
- **AC2**：补记非当天日期的流水后，日历正确落位

### F-05 备注与凭证（M1）
- 备注自由文本；凭证图 ≤3 张，JPEG 压缩存储（长边 ≤1200px）
- **AC1**：删除流水时凭证图级联删除
- **AC2**：凭证在流水详情/编辑页可查看（M1 支持查看与追加）

### F-06 预算（M1）
- 总预算 + 分类预算（月度）；预算页显示当月已用进度条，超支变红
- **AC1**：当月已用 = 明细页当月支出总额
- **AC2**：设置/修改预算立即反映到进度条

### F-07 周期记账（M1）
- 规则：名称/类型/金额/分类/账户/频率（每天 N 天、每周周 X、每月 X 号、每年）/起止日期/开关
- App 启动时自动补入到期流水（漏开 App 多天也逐期补齐，`lastPostedDate` 幂等）
- 支持手动「立即入账」一次
- **AC1**：跨多个周期未打开 App，启动后逐期补齐且不重复（有单测）
- **AC2**：关闭的规则不再产生流水

### F-08 数据与安全（M1）
- CSV 导出（UTF-8 BOM，Excel 中文不乱码），列：日期/类型/分类/账户/转入账户/金额/备注
- iCloud 同步：`.automatic`，无 entitlement 自动降级本地
- App 锁：Face ID/密码（LocalAuthentication），后台返回即锁
- **AC1**：导出文件可用 Excel 打开且行数 = 流水数
- **AC2**：开启 App 锁后切后台再进入必须解锁

### F-09 截图 OCR 记账（M2：App 内路径已实现）
- **已实现**：明细页工具栏 / 我的 → 截图记账：相册选支付截图（≤5 张）→ Vision 中文 OCR → PaymentTextParser 解析金额（带标签行优先、否则取最大候选）/ 时间 / 收款方 → 草稿可编辑 → 逐笔保存
- **待实现（M2 后半）**：Share Extension 分享入口（支付后直接截图分享到 App），需 App Group 与主 App 交换数据
- 验收：主流支付宝/微信支付成功页截图识别金额成功率 ≥90%

### F-10 账单导入（M2：App 内路径已实现）
- 我的 → 账单导入：选择 CSV（自动识别支付宝/微信格式，兼容 GB18030 编码）→ 预览（可导入/重复/剔除统计）→ 支付方式→账户映射（按关键词智能预填）→ 导入
- 查重：交易单号精确匹配 + 「方向/时间(分钟)/金额」模糊匹配，批内与历史账目双路去重
- 噪声剔除：退款、未完成、不计收支、转账中性行自动跳过
- 验收：1000 条账单导入 <5s，重复项 0 误并入

### F-11 AI 能力（M3 规划）
端侧优先（iOS 26 Foundation Models），云端可选：
1. 自然语言记账（「昨天和同事吃火锅 AA 花了156」→ 结构化交易）
2. 语音记账（Speech + LLM 解析）
3. 截图智能解析（Vision + LLM）
4. 智能分类（历史习惯 + 商户名，低置信度才询问）
5. 月度 AI 解读（洞察/异常/省钱建议）
6. 账本问答（「这个月咖啡花了多少」）
7. 导入账单智能清洗
8. AI 预算助手

### F-12 自动截图记账（M2 后半，Tier 1，ADR D15）
- **触发**（用户一次性配置，App 内提供分步指引页）：系统快捷指令自动化——当关闭支付宝/微信（App 列表可配置）时：拍摄屏幕快照 → 调用轻记「截图入账」App Intent → **删除该快照**
- **处理**：轻记静默 OCR → 按「支付成功页特征」判定（付款金额/交易时间/收款方等关键词 + 金额）
- **判定为支付页** → 本地通知确认卡（金额/商户/时间 + 「入账」「忽略」按钮）；**判定失败 → 完全静默，零打扰**
- 可选「静默自动入账」模式：关闭确认后，识别成功直接入账（必过 F-14 防重）
- 设置项：触发 App 开关（支付宝/微信/关）、确认式/自动式切换、防重灵敏度（联动 F-14）
- App 内「**自动入账记录**」页：所有机器入账按时间列出，每条带**撤销**按钮
- **AC1** 自动化触发后 ≤5 秒给出结果（通知或静默跳过）
- **AC2** 非支付页截图（聊天/浏览等）零通知
- **AC3** 同一支付页多张截图仅入账一次（F-14 第 2 道指纹）
- **AC4** 快照删除后相册无残留
- **AC5** 每笔自动入账均可单独撤销

### F-13 相册扫描记账（M2 后半，Tier 2，ADR D15）
- 打开轻记时**增量**扫描相册新增截图 → 筛出支付类页面 → 批量确认卡（复用 F-12 的识别与通知组件）
- 已处理过的截图（asset 标识 + 指纹）不再重复弹出
- 零自动截屏、零隐私顾虑；用户不截图的账靠 F-10 导入兜底
- **AC1** 只弹新增且未处理的支付类截图，已处理不重弹
- **AC2** 批量入账逐条经过 F-14 防重闸门
- **AC3** 拒绝照片权限时入口隐藏并给出开启引导

### F-14 统一防重闸门（M2 后半，**最优先**，ADR D16）
五道防线，全部本地计算：
1. **交易窗口闸门（DuplicateGuard，核心）**：新账目与已有账目「同方向 + 同金额 + 时间差 ≤10min」→ 疑似重复。手动/确认式：弹「疑似重复：xx:xx 已有 -¥45.60 美团外卖」，可强制保存；自动式：静默跳过并记日志。**所有入账入口（手动/OCR/导入/通知/自动）强制经过**
2. **截图指纹**：金额 + 页面交易时间(分) + 商户 哈希，7 天过期（§4.4）；同一页面多张截图只处理一次
3. **导入互斥**：BillDedup 由「分钟精确 key」升级为 **±10min 窗口查询**，交易单号精确匹配保留为第一层——使截图流与导入流可同时开启互补
4. **周期幂等**：lastPostedDate（M1 已实现，有单测）
5. **可撤销可配置**：`source` 来源标记（§4.1）、自动入账清单撤销（F-12）、灵敏度三档（仅提醒 / 提醒+确认 / 阻止）
- **AC1** 手动记入 10 分钟内同额同向账 → 弹疑似重复提示且可强制保存
- **AC2** 自动入账遇疑似重复 → 跳过且可在日志查看
- **AC3** 同一支付页两张截图 → 仅一笔入账
- **AC4** 截图已入账的笔，月底导入含同一笔 → 自动跳过
- **AC5** 每笔账可查来源；自动入账可撤销且不影响他笔

## 6. UI/UX 规范

### 6.1 信息架构
底部 Tab 5 位：**明细 ｜ 图表 ｜ ＋(记账) ｜ 日历 ｜ 我的**。中间「＋」为弹层，不驻留 Tab。

### 6.2 设计原则
1. 单手可达：核心操作集中在屏幕下半部
2. 数字优先：金额大字号（记账页 44pt+），次要信息弱化
3. 暖色系品牌色（橙 #FF8A3D），克制用色：支出主色文本、收入绿 `#34C759`、转账蓝 `#007AFF`
4. 圆角卡片（12pt）、分组背景 `systemGroupedBackground`
5. 空态必须给引导文案与行动按钮（如日历空日「补一笔」）

### 6.3 金额展示约定
- 支出：`-¥12.50`（主文本色）｜ 收入：`+¥3,000.00`（绿）｜ 转账：`¥500 →`（蓝）
- 分组分隔符 `,`；恒定 2 位小数；千位以上不加「万」缩写（列表内）

## 8. 风险与约束

| 风险 | 影响 | 对策 |
|---|---|---|
| iOS 无法监听支付宝/微信通知 | 「全自动记账」不可行 | 明确产品话术为准自动（截图/导入）；文档 §1.4、D8 |
| CloudKit 免费开发者账号限制 | 无付费账号时 iCloud 能力不可用 | `.automatic` 自动降级本地；数据结构保持 CloudKit 兼容 |
| 无本机 Xcode | 编译错误发现滞后 | CI 首要职责即编译验证；代码保守用稳定 API |
| `#Predicate` 枚举/可选链兼容性 | 运行时崩溃/编译失败 | D6/D7 决策规避 |
| 云端 LLM 成本与合规 | M3 成本失控/备案压力 | 端侧优先；云端需用户 Key 或订阅；上架前补生成式 AI 合规评估 |
| 照片凭证体积 | iCloud 配额/同步慢 | externalStorage + 压缩至长边 1200px、JPEG 0.6 |
| 自动截图的隐私顾虑 | 用户信任度 | 快照移交后立即删除（快捷指令「删除照片」动作）、全本地解析、设置一键关闭；提供 Tier 2（F-13）无截屏替代路线 |
